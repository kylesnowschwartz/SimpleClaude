# Context: GitHub issues

Give the maintainer the facts needed to reproduce the bug or evaluate the feature request.

For bug reports, state the observed behavior, expected behavior, and shortest reproduction steps. Include known relevant versions, the OS or runtime, and a link to the affected commit or release. Put stack traces, error messages, and commands in fenced code blocks so readers can copy them. Skip "Hi team" and the story of how you found the bug.

For feature requests, describe the concrete scenario before proposing an API or fix. This gives the maintainer the facts needed to evaluate the proposal.

Use a short imperative or symptom statement for the title: *Crash on empty config* or *Add `--dry-run` to `deploy`*. Avoid vague titles such as *Issue with deploy command (please help)*.

Always check if the repo has contributing guidelines, or issue templates, and adhere to them exactly.
